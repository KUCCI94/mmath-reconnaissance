1.4 백엔드 통신 아키텍처 (RPC 안티패턴 & 캐싱 부재)

모든 데이터 통신이 리소스 기반 REST API가 아닌 /proc/{area}/{controller}/{Action}Async 규격의 ASP.NET RPC 패턴으로 구현되어 있습니다.

엔드포인트 URL Method 호출 목적 및 기술적 결함
/proc/center/main/MyClassListAsync POST 강사 학급 및 원생 집계 통계 호출. 단순 조회임에도 POST로 전송하여 HTTP 캐싱 전무.
/proc/center/main/DashBoardInfoAsync POST 시험지 단계별 누적 건수 호출. 새로고침 시마다 DB 프로시저 락 유발.
/proc/center/main/NoMarkedPaperList4PreStudentAsync POST 미채점 시험지 목록 조회. 연속형 정수 식별자(f_study_id) 무단 노출.
/proc/common/CheckLoginStatus GET 서버 메모리 세션 동기 핑 체크. 서버 Scale-out 불가를 초래하는 원인.
/proc/common/GetChannelTalkUserInfo GET CRM 사용자 정보 조회. 관리자 영업 메모와 고객 실명 평문 전송.
인프라 응답 헤더와의 상관관계 분석:
헤더의 cache-control: private와 /proc/* RPC 엔드포인트의 POST 남발이 결합되어, 인프라의 모든 Edge/Browser 캐시 계층이 완벽히 무력화되어 있습니다. 수백 명의 강사가 시험 기간에 동시 조회를 누르면 모든 패킷이 윈도우 IIS와 단일 DB 서버를 직접 강타합니다.

인프라 효율 ASP.NET 4.0 모놀리스, POST 남발로 캐시 전무 Edge CDN 캐싱 및 컨테이너 무중단 자동 확장

프론트엔드 체계 jQuery + Vue 3 Standalone 비빔밥 혼용 Next.js 15 App Router 기반 통일된 아키텍처

2.0 마스터 설계 헌법 (Immutable Architecture Rules)

제1조 [Clean Modular Monorepo & Zero-Coupling Bounded Context]
Turborepo 기반 격리 (apps/web, apps/api, packages/schema, packages/database). 타 도메인 테이블의 직접 JOIN이나 외부 키 강결합을 엄금하며, UUID v7 논리 식별자, 퍼사드, 도메인 이벤트로만 통신한다.
제2조 [Dual-Write 방어 & Transactional Outbox 비동기 이벤트 보장]
DB 트랜잭션과 외부 I/O(포트원 V2, 솔라피 알림톡)의 동기 결합을 엄금한다. 동일 트랜잭션 내 Outbox 레코드 적재 후, 멱등성이 보장된 비동기 메시지 릴레이를 통해 전파한다.
제3조 [장애 격리 및 복원력 (Resilience by Default)]
외부 3rd Party 연동 지점에 타임아웃, 지수 백오프 기반 재시도(with Jitter), 서킷 브레이커, DLQ를 기본 탑재한다. 영구 장애 시 Fallback 및 보상 트랜잭션을 강제한다.
제4조 [K-Compliance Lifecycle Engineering (개인정보 수명주기 설계)]
모든 PII는 AES-256-GCM으로 암호화하고 SHA-256 동등 검색 해시 인덱스를 물리 분리한다. 로그 마스킹을 강제하며 법적 보관 주기 경과 시 자동 파기 배치를 가동한다.
제5조 [Strict Task Atomicity & Directed Acyclic Graph (DAG) Decomposition]
후속 AI 코딩 에이전트 주입을 위해 각 Task는 예상 수정 파일 3~5개 이내로 엄격히 쪼개며, 생략(Zero Truncation) 없이 명확한 선행 의존성(Depends on)을 명시한다.

2.1 Executive Summary & Core User Journey

비즈니스 목표 및 핵심 KPI

메타수학 레거시의 기술 부채를 완전히 청산하고, Next.js 15 + NestJS + KaTeX 기반의 엔터프라이즈 모노레포 SaaS로 재구축합니다. 학원 강사의 시험지 조판 시간을 85% 단축하고, OMR 실시간 채점 및 오답 쌍둥이 클리닉지 자동 생성 파이프라인을 완성합니다.

Client (Next.js 15) 
  │ [Bearer JWT]
  ▼

  ▼

비기능 요구사항(NFR) 및 스케일링 전략

  • 목표 TPS: 문항 색인 3,000 TPS, 채점/출제 피크 6,000 TPS 수용.
  • 분산 ID 체계: 시간순 정렬 보장 및 인덱스 단편화 방지를 위한 UUID v7 Prefixed ID (qst_01h..., exm_01h..., pay_01h...).
  • DB 커넥션 풀 가드: PgBouncer 트랜잭션 풀링 모드 적용 (statement_cache_size=0).
  • 멀티테넌시 격리: 모든 도메인 테이블에 tenant_id 복합 인덱스 부여 및 Prisma Client 미들웨어를 통한 논리적 데이터 격리.
  • 캐시 전략: 정적 교육과정 메타데이터는 Redis Cache-Aside 패턴(TTL 24시간) 적용.

PaymentSubscription buyerPhone, customerKey AES-256-GCM / SHA-256 Hash 5년 전자상거래법 (구독 해지 후 콜드 아카이빙 DB로 물리 분리보관)

2.4 External Integration & Reliability Spec

결제 파이프라인 (포트원 V2 REST API)

정기 결제 빌링키 발급(POST /payments/billing-key) 및 자동 결제 승인. 웹훅 수신 시 HMAC-SHA256 서명 검증 및 단건 조회 API(GET /payments/{paymentId}) 교차 검증을 필수화하며, DB idempotency_key 테이블의 복합 유니크 제약(tenant_id, payment_id, event_type)으로 중복 처리를 원천 차단합니다.

메시징 파이프라인 (솔라피 비즈엠 알림톡/SMS)

채점 완료 시 DB Outbox 테이블에 EVENT_REPORT_READY를 적재하고, 비동기 워커가 카카오 알림톡 템플릿을 바인딩하여 발송합니다. 알림톡 수신 실패 코드(카카오 미사용/차단 등) 수신 시 즉시 솔라피 SMS/LMS로 자동 재시도 Fallback을 수행합니다.

장애 격리 및 보상 트랜잭션 (Compensating Transactions)

  • 외부 API 연속 5회 5xx 또는 타임아웃(3초 초과) 발생 시 서킷 브레이커를 즉시 Open하여 트래픽 전파를 차단합니다.
  • 결제 승인 완료 후 내부 DB 멤버십 갱신 트랜잭션 실패 시, 포트원 자동 망취소/환불 API를 멱등하게 호출하여 사용자 과금을 자동 복구합니다.
